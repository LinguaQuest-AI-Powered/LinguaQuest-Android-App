# CI/CD Pipeline Documentation

## Overview
LinguaQuest utilizes GitHub Actions to automate the build process for the application. Whenever code is pushed or a pull request is merged into designated branches (such as `dev` or `ci-test`), the pipeline triggers automatically to compile the code, generate a debug APK, and upload it as a downloadable artifact.

## Workflow File
The pipeline configuration is located at `.github/workflows/build-debug-apk.yml`. 

### Key Steps
1. **Checkout & Setup:** The repository is checked out and JDK 17 is configured.
2. **Secrets Injection:** The `BASE_URL` and `GEMINI_API_KEY` are read from GitHub Repository Secrets and injected into a dynamically generated `local.properties` file. This ensures that sensitive keys are not exposed in the codebase while still allowing the build system to generate the `BuildConfig` variables.
3. **Build APK:** The Gradle wrapper executes `./gradlew assembleDebug` to build the app.
4. **Upload Artifact:** The generated `app-debug.apk` is uploaded to the workflow run using the `actions/upload-artifact` action.

## Keystore & Firebase
Because Firebase Authentication (specifically Google Sign-In and EncryptedSharedPreferences) relies on the cryptographic signature of the app, generating debug builds on a CI server poses a challenge: every developer's local `debug.keystore` is different, and the CI server has its own default keystore.

To resolve this and maintain persistent signatures:
1. **Shared Keystore:** A shared debug keystore (`ci-debug.keystore`) was generated and committed to the repository at `app/keystore/ci-debug.keystore`.
2. **Gradle Configuration:** The `app/build.gradle.kts` file is configured to use this shared keystore specifically for the `debug` build type.
3. **Firebase Console:** The SHA-1 and SHA-256 fingerprints of this shared keystore were added to the Firebase Console. 
4. **Result:** Whether you build the app locally on your machine or download the APK generated by GitHub Actions, the signature will be identical, and Firebase Authentication will work seamlessly.

## How to Test
1. Push a commit to the `ci-test` branch.
2. Navigate to the **Actions** tab on your GitHub repository.
3. Click on the running workflow for your commit.
4. Once the build succeeds, scroll down to the **Artifacts** section to download the `app-debug.apk`.
